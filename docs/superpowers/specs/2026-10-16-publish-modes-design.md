# publish 모드 확장: 예선모드, 본선모드, 기본 publish

날짜: 2026-10-16. 상위 설계: `2026-07-30-kimchi-resolver-design.md` §13.

## 1. 목적과 이유

지금의 publish 모드는 본선만 대상으로 합니다. 이 모드는 APAC 진출 별을 표시합니다.
운영자는 이 기능을 예선 결과 공지에도 사용하려고 합니다. 그리고 본선 결과는 올해
APAC 규칙(2026-27)에 맞추어야 합니다. 또한, 지금은 `dist/` 전체(spectator, award
코드와 `config.json` 포함)를 S3에 올립니다. 공개할 것은 순위표 하나입니다.

## 2. 목표, 비목표, 실패 조건

목표:

- config 값 하나로 publish 기능을 `off`, `preliminary`, `regional` 중에서 고릅니다.
  디폴트는 `off`입니다.
- 브라우저의 **prepare 페이지**에서 운영자(심사위원)가 값을 바꾸면서 결과를 바로
  확인합니다.
- `npm run publish`가 공개용 정적 파일을 만듭니다. 이 파일은 judge API를 호출하지
  않습니다. 운영자가 이 파일을 S3에 직접 올립니다.

비목표:

- S3 업로드 자동화. `npm run publish`는 파일만 만듭니다.
- APAC 전체 리저널 병합(D4), 국가별 와일드카드, 총 팀 수 P, 감독 와일드카드(D5),
  사퇴 처리(E 규칙)의 계산. 이 값들은 모든 리저널이 끝나야 정해집니다.
- 예선 페널티(무단 불참 학교 페널티 등)의 자동 계산. 운영자가 미자격 체크로
  처리합니다.

실패 조건 (기능이 동작해도 실패):

- 공개 파일에 credential, `config.json`, judge URL, awards.json 파일이 들어갑니다.
  (최종 결과(freeze 해제 후 standings)는 공개 대상입니다. `npm run publish`는
  credential 문자열과 judge URL만 검사합니다.)
- 예선 공개 페이지에서 방문자가 진출 결과를 바꿀 수 있습니다.
- 본선 시뮬레이션 페이지가 공식 결과처럼 보입니다.

## 3. config

`publish` 블록에 `mode`를 추가합니다.

```jsonc
"publish": {
  "enabled": false,          // 기존과 같음: prepare 페이지로 들어가는 스위치
  "mode": "off",             // "off" | "preliminary" | "regional"
  "preliminary": {
    "totalTeams": null,      // 본선 진출 팀 수 (정수 ≥ 1)
    "topN": 30,              // 2단계: 학교 무관 상위 N팀
    "k": null,               // 3단계: 학교 대표 팀의 최소 해결 문제 수
    "ineligibleTeamIds": []
  },
  "regional": { /* §6.4의 시뮬레이션 초기값 */ },
  // 기존 siteScore, invitedScoreCutoff, alreadyInvited는 §6.5 참고
}
```

URL 파라미터 `publish_mode=off|preliminary|regional`가 config보다 우선합니다.
`apac.enabled`는 award 모드에서만 의미가 있습니다. publish에서는 `mode`가 별 표시를
결정합니다.

## 4. 전체 흐름 (세 모드 공통)

1. 운영자가 대회 종료 후 operator 빌드에서 `?publish=true`로 prepare 페이지를
   엽니다. (judge credential이 있는 빌드입니다. 공개하지 않습니다. 운영 문서 §3.)
2. prepare 페이지에서 값을 확인하고 바꿉니다. 입력값은 그 브라우저의
   `localStorage`에 저장합니다. 새로고침해도 값이 남습니다. key는 대회 id와 mode를
   포함합니다. 그래서 예선 값이 본선에 섞이지 않습니다. 저장된 값이 있으면 그 값이
   config/URL 값보다 우선합니다. 이때 prepare 페이지에 "저장된 값을 사용 중"이라고
   표시하고 "config 값으로 되돌리기" 버튼을 둡니다. (빌더 결정.)
3. 운영자가 **"확정 결과 저장"** 버튼을 누릅니다. 확인 창에 저장할 모든 입력값과
   결과 요약을 표시합니다. 운영자가 확인하면 브라우저가 `publish-state.json`을
   다운로드합니다.
4. 운영자가 `npm run publish -- <publish-state.json 경로>`를 실행합니다.
5. 이 명령이 `publish-dist/` 폴더를 만듭니다. 운영자가 이 폴더를 S3에 올립니다.

`publish-state.json` 내용:

- `schemaVersion`, `mode`, 생성 시각.
- 대회 제목, 문제 목록(label, 이름, 색).
- 최종 standings: 각 팀의 id, 이름, 학교, 국가 코드, foreign 여부, rank, 해결 수,
  penalty, 문제별 셀 결과(정답 여부, 시도 수, 정답 시각, first solve 여부).
  공개 보드가 표시하는 값만 넣습니다. run 목록 전체는 넣지 않습니다.
- 모드별 확정값 (§5.3, §6.4).

`publish-dist/` 구성:

- `index.html`, JS/CSS 번들. 이 번들은 publish 전용 entry입니다. spectator, award,
  feed, ingest 코드는 들어가지 않습니다.
- `data.json` (`publish-state.json`에서 필요한 값만 옮긴 것).
- 이 대회에 나온 학교의 로고와 국기 파일만 복사합니다 (`showSchoolLogos`가 켜진
  경우).
- `config.json`, `sample/`, `awards.json`은 들어가지 않습니다.

`npm run publish`는 입력 파일을 zod로 검사합니다. 잘못된 값이 있으면 이유를 출력하고
실패합니다 (exit code ≠ 0). 결과 폴더에 credential 문자열이나 judge URL이 없는지
검사합니다 (`check-config-security.mjs`와 같은 방식).

## 5. 예선모드 (`preliminary`)

기준: [2026 ICPC Seoul 예선 공지 6번 항목](https://icpckorea.org/archives/3475).

### 5.1 선발 알고리즘

입력: 최종 standings, 진출 팀 수 T, 상위 N, K, 미자격 팀 집합.

1. 미자격 팀을 모두 순위표에서 제외합니다 (선발 대상이 아닙니다).
2. 남은 팀 중에서 standings 순서로 상위 N팀을 선발합니다. 학교는 보지 않습니다.
3. 2단계에서 **한 팀도 선발되지 않은 학교**만 대상으로 합니다. 각 학교의 최상위
   팀(미자격 제외)이 K문제 이상을 해결했으면 그 팀을 선발합니다. 최상위 팀이
   K문제 미만이면 그 학교는 3단계에서 선발되지 않습니다. 학교 안의 다음 팀은 보지
   않습니다. (운영자 확인: "해석 1".)
4. 선발된 팀 수가 T 미만이면, 아직 선발되지 않은 팀을 standings 순서로 T팀이 될
   때까지 선발합니다.

규칙:

- 2단계와 3단계의 합이 T보다 크면, 4단계는 선발하지 않습니다. 이 경우에도 3단계의
  모든 팀을 선발합니다. prepare 페이지에 "선발 팀 수가 T를 넘습니다 (X팀)"라는 경고를
  표시합니다. (빌더 결정: 규정은 3단계에 상한을 두지 않습니다.)
- 학교 이름이 빈 문자열인 팀은 각각 별개의 학교로 봅니다 (기존 APAC 규칙과 같음).
- 순위가 같은 팀은 standings 순서를 따릅니다. 선발 경계(N번째, T번째)에서 같은
  순위의 팀이 갈리면 prepare 페이지에 경고를 표시합니다. 자동으로 해결하지 않습니다.
- 각 선발 팀은 선발 단계(2, 3, 4)를 가집니다.
- T, K가 비어 있으면 선발 표시를 하지 않습니다. prepare 페이지에 입력 안내를
  표시합니다.

### 5.2 prepare 페이지

- 입력: 진출 팀 수 T, 상위 N (디폴트 30), K.
- 각 행에 "미자격" 체크박스가 있습니다.
- 값을 바꾸면 결과가 바로 바뀝니다.
- 선발된 행의 배경은 노란색입니다. 행에 선발 단계 아이콘을 둡니다. 상위 =
  연단과 별(파랑), 학교 = 학사모(초록), 추가 = 원 안의 더하기(자홍). 글자 태그("상위",
  "학교", "추가")는 쓰지 않습니다. 아이콘에 마우스를 올리면 뜻이 나옵니다 (tooltip,
  aria-label). 공개 페이지에도 같은 아이콘을 표시합니다 (§5.3). (2026-10-17 운영자
  요청.)
- 요약 줄: "진출 X팀 = 상위 a + 학교 대표 b + 추가 c". 요약 줄 아래에 범례를 둡니다:
  아이콘 + 한국어 뜻 + 저장된 N, K와 단계별 팀 수.
- 미자격 팀 행은 opacity 50%입니다.
- 모바일 레이아웃은 필요 없습니다 (운영자 노트북).

### 5.3 확정값과 공개 페이지

`publish-state.json`에 들어가는 값: T, N, K, 미자격 팀 id 목록, 그리고 **계산된**
선발 팀 id 목록.

공개 페이지:

- 입력란이 없습니다. 선발 결과는 저장된 목록을 그대로 표시합니다. 다시 계산하지
  않습니다.
- 선발된 행의 배경은 노란색입니다. 범례: "노란색 = 본선 진출".
- 선발된 행에 선발 단계 아이콘(상위, 학교, 추가)을 표시합니다. 글자 태그는 쓰지
  않습니다. 아이콘의 뜻(tooltip, aria-label)은 한국어와 영어로 바뀝니다. 범례의 각 줄은
  아이콘으로 시작하고, 뜻과 팀 수를 저장된 N, K 값으로 표시합니다. 예: "[상위 아이콘]
  학교와 상관없이 상위 30팀 (30팀)", "[학교 아이콘] 3문제 이상 해결한 학교의 1위 팀
  (12팀)", "[추가 아이콘] 남은 자리를 순위대로 채운 팀 (8팀)". 영어: "[icon] Best 30
  teams regardless of school (30 teams)". (2026-10-17 운영자 요청.)
- 미자격 팀은 순위표에 남고, opacity 50%입니다. "미자격"이라는 글자는 표시하지
  않습니다.
- 순위 숫자는 원래 standings의 순위를 그대로 표시합니다. (빌더 결정.)
- APAC 별은 표시하지 않습니다.
- 데스크톱과 모바일 레이아웃을 모두 지원합니다 (기존 §14 모바일 규칙).

## 6. 본선모드 (`regional`)

기준: [ICPC Asia Pacific 2026-27 rules](https://icpc.jp/apac/2026-27/rules/).
공개 페이지를 보는 사람은 **참가 학생**입니다. 학생은 "우리 팀이 APAC
Championship에 갈 수 있는가?"를 확인합니다.

### 6.1 2025-26 규칙과 다른 점

- site score S를 공식으로 계산합니다 (C1):
  `S = 0.56·U_r + 0.24·T_r + 0.14·U_p + 0.06·T_p + 0.30·F_r`
  - U_r, T_r: 본선의 학교 수, 팀 수. F_r: 본선의 외국 팀 수.
  - U_p, T_p: 예선의 학교 수, 팀 수.
  - 1문제 이상 해결한 팀만 셉니다. 학교 수는 그런 팀이 있는 학교의 수입니다.
  - F_r는 국가 코드가 있고 `KR`이 아닌 팀입니다. `team.foreign`(국내 순위용
    `config.foreign`)은 사용하지 않습니다. 국가 코드가 없는 팀은 국내 팀으로 셉니다.
  - super-region 팀(AU, NZ)도 S에는 셉니다 (규정). 계산 리스트에서만 제외합니다.
    (빌더 결정.)
- 학교별 상한 Q (C2): 작년 World Finals 메달 학교는 3, 다른 학교는 2입니다.
  2025-26에는 모든 학교가 3이었습니다.

### 6.2 계산 (D3, 이 리저널만)

1. South Pacific 등 super-region 팀을 제외합니다. (서울 리저널에는 보통 없습니다.
   국가 코드 AU, NZ 팀을 제외합니다. 내부 국가 코드는 alpha-2입니다.)
2. 0문제 팀을 제외합니다.
3. 제외 학교의 팀을 모두 제외합니다. 제외 학교 = 이 대회 1위 팀의 학교 + 다른
   리저널 winner 학교 + 다른 경로로 이미 초청된 학교. (운영자 결정 "B": D3(3)는
   winner 학교만 쓰지만, 2025-26 Seoul 공표 리스트를 재현한 지금 방식을 유지합니다.)
4. 각 학교에서 상위 Q팀만 남깁니다.
5. 남은 팀에 순위 R(1부터)을 다시 매깁니다. value = (R − 1) / S.

`src/core/apac.ts`의 `computeApacFilteredRanks`를 이 규칙으로 바꿉니다. 고정 상한
`APAC_SCHOOL_RANK_CAP = 3`을 학교별 Q로 바꿉니다. award 모드의 동색 별 규칙(학내
3등 이내)은 바꾸지 않습니다.

award 모드도 같은 함수를 사용합니다 (코드 경로 하나). award 모드는 Q=3 학교를
`config.publish.regional`의 WF 메달 학교 목록에서 읽습니다. award 모드에는 입력란이
없습니다. (빌더 결정.) 2025-26 Seoul 재현 테스트는 2025-26 파라미터(모든 학교 Q=3,
S 직접 지정)로 계속 통과해야 합니다. 그래서 core 함수는 Q와 S를 인자로 받습니다.

### 6.3 별과 표시

- 금색: 이 대회 1위 팀, `alreadyInvited.teamIds`에 있는 팀(config 전용, 학교
  선택기로는 팀을 고를 수 없습니다), 그리고 value ≤ 가정 cutoff인 팀. 제외 학교의
  다른 팀은 금색이 아닙니다.
- 은색: 계산 리스트에 있고 cutoff를 통과하지 못한 팀.
- 동색: 리스트 밖이지만 학내 3등 이내인 팀 (기존 규칙과 같음).
- 리스트에 있는 각 행에 value를 소수점 4자리로 표시합니다.
- cutoff가 비어 있으면 금색은 winner 팀에만 있습니다.

### 6.4 입력과 초기값

입력 (prepare 페이지와 공개 페이지 모두):

| 입력 | 디폴트 | 비고 |
|---|---|---|
| 예선 학교 수 U_p | 운영자 입력 | |
| 예선 팀 수 T_p | 운영자 입력 | |
| S 계수 5개 | 0.56, 0.24, 0.14, 0.06, 0.30 | "고급" 영역에 접어 둡니다 |
| U_r, T_r, F_r | standings에서 자동 계산 | 표시만 하고, 직접 바꿀 수도 있습니다 |
| 작년 WF 메달 학교 (Q=3) | 운영자 선택 | 기존 학교 선택기를 다시 사용 |
| 다른 리저널 winner 학교 | 운영자 선택 | 리스트에서 제외 |
| 다른 경로로 이미 초청된 학교 | 운영자 선택 | 리스트에서 제외 |
| 가정 cutoff | 비어 있음 | |

- 계산된 S를 화면에 표시합니다.
- 운영자가 prepare 페이지에서 입력한 값이 공개 페이지의 초기값입니다.
- 공개 페이지에서 학생이 값을 바꿀 수 있습니다. 바꾼 값은 저장하지 않습니다.
  새로고침하면 초기값으로 돌아갑니다. "초기값으로 되돌리기" 버튼이 있습니다.
- 각 입력란에 짧은 한국어 설명이 있습니다. 규정 링크(icpc.jp)를 표시합니다.
- 페이지 위쪽에 고정 안내: "이 페이지는 시뮬레이션입니다. 공식 결과가 아닙니다.
  최종 초청은 모든 리저널이 끝난 다음 APAC에서 정합니다."
- 공개 페이지는 데스크톱과 모바일을 모두 지원합니다. 모바일에서 입력 영역은
  접힌 상태로 시작합니다.

### 6.5 기존 값

- `publish.siteScore`: 지금은 직접 입력입니다. 본선모드에서는 공식으로 계산합니다.
  직접 입력 기능은 없앱니다. (빌더 결정: 계수와 입력값으로 같은 결과를 만들 수
  있습니다.)
- `publish.invitedScoreCutoff`: 가정 cutoff의 초기값으로 사용합니다.
- `publish.alreadyInvited`: 유지합니다. `groups`에 `winnerGroups`와 `invitedGroups`
  두 목록을 둡니다 (계산에서는 같게 처리하고, 화면에서는 두 입력란으로 나눕니다).
  기존 `groups` 값은 `invitedGroups`로 읽습니다. `teamIds`는 그대로 둡니다.
- 기존 URL 파라미터 `site_score`는 없앱니다. `invited_cutoff`는 남깁니다.

## 7. 기본 publish (`off`)

- prepare 페이지: 최종 순위표만 표시합니다. 입력란이 없습니다. "확정 결과 저장"
  버튼만 있습니다.
- 공개 페이지: 최종 순위표만 표시합니다. 노란 행, 별, 시뮬레이션 입력이 없습니다.
- 지금처럼 site score 입력을 기다리는 gate는 없습니다.

## 8. 공통 화면 규칙

- 공개 페이지 헤더: 대회 제목, 모드 표시가 없습니다. 지금의 시계는 없앱니다
  (정적 결과이므로 의미가 없습니다).
- awards.json 칭호: prepare 페이지에서 로드되면 `publish-state.json`에 넣습니다.
  (빌더 결정. 공개 파일에는 칭호 문자열만 들어갑니다.)
- 문서 업데이트: `docs/operations.md` §6 Step 4를 새 흐름으로 바꿉니다. 상위 설계
  문서 §13에 이 문서 링크를 추가합니다.

## 9. 빌더에게 맡긴 것

  다크/라이트 배경에서 읽기 쉬운 값).
